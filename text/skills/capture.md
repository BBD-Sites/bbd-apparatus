# Capture

## When to use
Use this when the owner dumps something: a thought, a link, a file, a recording, a plan, or a list of many things. Decide for each piece: capture, file, or change.

## Steps
1. Capture. Keep the raw thing whole in 00-inbox/ as a dated page. Never shorten it.
2. File. If it belongs to a project or area you know, add it there: a to-do as a line, a fact as a page, linked from where the owner would look.
3. Change. If it describes something to build or change, use the spec interview skill to extend the open change or start one.
4. If a dump holds several things, do each one now. Do not ask the owner which is which.
5. Report in a few lines: what was kept, where, and what is still open.
6. Files. Plain text goes in the vault. A file that is not text and is within the size limit goes in attachments/, cited from its page. A bigger one never goes in git. It stays where it is, and its page says where. The place for it is named below.
7. The upload of big files is not built yet. Until it is, make the page, name the file and its place, and say in one line that the upload waits. Never drop it and never put it in git.
8. If something cannot be fetched here, write that down as not fetched and retry it on the desktop. Never fill it in from memory.

## Never
- Never ask the owner where something goes.
- Never summarize a capture in place of keeping it whole.
- This skill sends nothing to anyone. It writes files in the repository.
